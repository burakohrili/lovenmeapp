# Lovenme Admin and Review Readiness

## Current Admin Access

- There is no deployed web admin panel configured in `firebase.json`.
- `web/admin/` is intentionally ignored by Git for local-only admin tools.
- A local web admin panel is available at:
  `web/admin/index.html`
- The only existing in-app admin screen is:
  `lib/presentation/pages/admin/sponsor_admin_page.dart`
- That screen is not routed from the app, so normal users/reviewers cannot open it.

## Local Admin Panel Use

Run a local static server from the project root and open:

`http://localhost:4177/`

The panel signs in with Firebase Auth and reads:

- users
- completed profiles
- venues
- check-ins when rules allow it
- sponsor status

Admin-only collections require the signed-in Firebase user to have custom claim:

`admin=true`

## Store Review Data Checklist

Before sending new builds to Apple/Google, prepare:

- At least 2 real-looking non-bot demo users.
- Both demo users must have completed onboarding.
- Demo users should have email, phone, age, interests, photos, and profile text.
- At least 5 venues should exist around the test area.
- At least 1 venue should have check-in history.
- At least 1 venue should demonstrate the mayor/muhtar mechanism.
- At least 1 pending connection request should exist.
- At least 1 accepted connection should show a working chat.
- At least 1 premium-visible benefit should be demonstrable without implying pay-to-message.
- Bot/admin endpoints must remain unavailable to reviewers in production.

## Apple Review Positioning

Reviewer demo should start from:

1. Map / nearby venues
2. Check-in
3. Venue community
4. Mayor/muhtar status
5. Encounter context
6. Connection request
7. Chat after accepted request

Avoid leading with profile swiping, match language, love/dating language, or super-like purchase mechanics.

Target admin email:

`brkohrili@gmail.com`

Use the `setAdminClaim` Cloud Function after deployment. The endpoint is protected by `BOT_ADMIN_SECRET`; without the secret it returns 404.

There is also a safer bootstrap flow for the owner account:

- Function: `bootstrapAdminClaim`
- Allowed email: `brkohrili@gmail.com`
- Call path: local admin panel button `Admin Yetkisini Etkinleştir`
- After success, sign in again so the new token includes `admin=true`.

Expected request body:

```json
{
  "email": "brkohrili@gmail.com",
  "admin": true
}
```

After the claim is set, sign out and sign back in from the local admin panel so Firebase refreshes the ID token.
